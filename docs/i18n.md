# Internationalisation (i18n)

This document explains where translation files live and how to add new keys.

## Translation Files

- **English**: `src/messages/en.json`
- **Georgian**: `src/messages/ka.json`

Both files share the same structure. Namespaces:

- `app` — App title, badge, tagline
- `nav` — Navigation labels
- `public` — Public pages (home, about, rules, events)
- `auth` — Login form
- `noAccess` — No-access page
- `admin` — Admin dashboard, sidebar, topbar, rulesets, events, users, settings, theme

## Adding a New Key

1. Open `src/messages/en.json` and `src/messages/ka.json`
2. Add the key under the appropriate namespace
3. Use in components: `useTranslations('namespace')` then `t('key')`

Example:

```json
// en.json
"public": {
  "newKey": "English text"
}

// ka.json
"public": {
  "newKey": "ქართული ტექსტი"
}
```

```tsx
const t = useTranslations('public');
return <span>{t('newKey')}</span>;
```

## Language Switching

- **Toggle**: EN/KA buttons in `TopbarToggles` (public topbar, admin topbar, login page)
- **Persistence**: `localStorage` key `gw_locale` and cookie `gw_locale`
- **Root redirect**: Visiting `/` redirects to `/{savedLocale}` or `/{defaultLocale}` based on cookie
- **Client-side**: `switchLocale` uses `router.push` (no full reload)

## Locale Restoration

- `LocaleRestoration` component runs on mount and redirects to saved locale if URL differs
- Ensures bookmarked `/en/events` with saved `ka` preference redirects to `/ka/events`

## Config

- **Locales**: `src/i18n/config.ts` — `locales: ['en', 'ka']`, `defaultLocale: 'en'`
- **Request config**: `src/i18n/request.ts` — loads messages per locale
